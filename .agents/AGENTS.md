# AGENTS.md — Developer & AI Agent Guide for SMD-Heatbed

This document provides developer guidelines, architectural rules, hardware specifications, and codebase navigation for AI agents and human developers working on **SMD-Heatbed**.

---

## 1. Project Overview

**SMD-Heatbed** is an open-source heatplate controller designed for reflow and SMT soldering work. It runs on a **Raspberry Pi Pico (RP2040)** paired with an **Elecrow 4.3" Pico DVI Display** running an **LVGL 8.3.11** touchscreen user interface.

### Key Hardware Specifications
* **MCU:** Raspberry Pi Pico (RP2040 microcontroller)
* **Heater Element:** 400W PTC Heatplate driven via a 3.3V Logic Solid State Relay (SSR)
* **Temperature Sensor:** 100K NTC Thermistor in a voltage divider ($R = 2.2\text{k}\Omega$, $R_0 = 100\text{k}\Omega$, $\beta = 3950$, $T_0 = 298.15\text{K}$)
* **User Input:** DFRobot Rotary Encoder with integrated push-button & Capacitive Touchscreen (GT911 driver)
* **Display:** 320x240 RGB display output driven via PicoDVI (`DVIGFX16`)
* **Telemetry:** Serial1 UART (TX: GPIO 0, RX: GPIO 1) at 115200 baud

## 4. Software Architecture & Control Loops

### 4.1 Timer Interrupt Handlers (`SMD-Heatbed.ino`)

The firmware uses hardware timer interrupts (`RPi_Pico_TimerInterrupt`) to handle control routines:

1. **Regulator Loop (`TimerMain`, 500 Hz / 2000 µs interval)**
   - Function: `regulatorHandler()`
   - Converts raw 12-bit ADC values from `PIN_NTC` to temperature in °C using Steinhart-Hart / Beta equation ($R = 2200\Omega$, $R_0 = 100000\Omega$, $\beta = 3950$).
   - Soft-start ramping: Increments `reference_temp` towards `set_temp` by `REF_STEP` (0.05°C per cycle) to prevent aggressive temperature overshoots.
   - PI Controller: Computes error ($e = T_{\text{ref}} - T_{\text{meas}}$) and output duty cycle ($\text{duty} = k_p \cdot e + k_i \cdot \int e\,dt$).
   - Duty cycle clamp: Bounded between `MIN_DUTY` (0%) and `MAX_DUTY` (40%).
   - Thermal Safety Check: Monitors thermal rise over `SAFETY_PERIOD` (18,000 ms). If temperature rise is less than `SAFETY_THRESHOLD` (2°C) while heating, the system enters `error_state` (NTC Error), zeroes duty cycle, and disables PWM.

2. **Input Acquisition Loop (`TimerAcqusition`, 5000 Hz / 200 µs interval)**
   - Function: `acquisitionHandler()`
   - Debounces rotary encoder push-button (`PIN_EBT`). Short press (<1000ms) toggles heater state (`toggleHeater()`); long press (≥1000ms) logs hold action.
   - Quadrature decoding of encoder rotation (`PIN_ENA`, `PIN_ENB`) updating set temperature (`set_temp` clamped between `MIN_TEMP` 0°C and `MAX_TEMP` 250°C).

3. **Telemetry & Update Trigger (`TimerLED`, 100 Hz / 10000 µs interval)**
   - Function: `printHandler()`
   - Triggers periodic UI refresh requests every `LCD_PERIOD` (1000 ms).

## 5. Critical Engineering Rules for AI Agents

> [!CAUTION]
> ### 1. Threading & LVGL Safety Rule (CRITICAL)
> **LVGL API calls are NOT interrupt-safe.** Never invoke LVGL GUI functions (e.g., `lv_label_set_text`, `lv_arc_set_value`, `lv_img_set_src`, `ui_object_set_themeable_style_property`) inside timer interrupt callbacks (`regulatorHandler`, `acquisitionHandler`, `printHandler`).
>
> **Pattern to follow:**
> - ISRs must only mutate `volatile` status variables (`ui_needs_update`, `ui_status_state`, `ui_temp_to_display`, `ui_set_temp_to_display`).
> - All actual LVGL GUI operations must be processed inside `loop()` context after `lv_timer_handler()`.

> [!IMPORTANT]
> ### 2. C / C++ Interoperability
> - SquareLine Studio generates pure C files (`ui_events.c`).
> - Firmware logic resides in C++ (`SMD-Heatbed.ino`).
> - Do not directly call C++ Arduino functions from `ui_events.c`. Always route events through `ui_events_wrapper.h` / `ui_events_wrapper.cpp` using `extern "C"` wrappers.

> [!WARNING]
> ### 3. Thermal & Duty Cycle Safety
> - `MAX_DUTY` is intentionally limited to 40% to protect the 400W heatplate and mains SSR. Do not alter `MAX_DUTY` or remove duty cycle bounds without explicit verification.
> - Maintain thermal runaway safety checks (`SAFETY_PERIOD` / `SAFETY_THRESHOLD`).

## 6. Build & Environment Instructions

### Target 1: Microcontroller Firmware (Arduino IDE / PlatformIO)
1. Board Package: Earle F. Philhower RP2040 / Raspberry Pi Pico core.
2. Required Arduino Libraries:
   - `PicoDVI`
   - `lvgl` (version 8.3.11)
   - `RPi_Pico_TimerInterrupt`
   - `RP2040_PWM`
   - `TAMC_GT911` (or corresponding touch library configured in `touch.h`)
3. Open `SMD-Heatbed.ino` and upload to Raspberry Pi Pico.

### Target 2: UI Desktop Simulator (CMake)
- Pre-configured VS Code tasks reside in `.vscode/tasks.json`.
- Run task `Configure` (`cmake -S sim -B build -DCMAKE_BUILD_TYPE=Debug` from `src/`) followed by `CMake build`.
